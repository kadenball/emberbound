- **209 simulation tests passed** across 23 files, including all nine earned-progression hero/style campaigns. Combat rules, progression, cargo physics and level layouts are unchanged from 0.26; its 432-run strategy audit was not rerun.
- The final complete browser suite passed **176 checks**, skipped ten inapplicable combinations and had **no failures** in one uninterrupted 5.1-minute run using two workers. Coverage includes actual UI campaign endings, rewards, story, bookmarks/storage failures, controllers, co-op, supplies, all six cargo interactions, boss warnings/defenses, move recipes, music transport/signal and the new audio recovery paths. Desktop Chromium, Android-sized Chromium and iPhone-sized WebKit are browser targets, not physical-device or native iOS proof. No product code changed after this run.
- Two new recovery regressions failed before the fix. The interrupted-state contract fixture really suspends a browser audio context, then overrides its state getter to expose `interrupted`; it asserts one resume attempt without changing mute/pause preferences. The live-game case calls the real context's `suspend()`, verifies combat pauses and chapter transport stops, then verifies restoring audio alone does not unpause. Explicit resume works; with both Music and SFX disabled, a stopped audio context does not interrupt play. The focused audio selection passed all 13 applicable checks before the full run, with two decoder cases skipped. The Android-sized pause capture was inspected; the notice and explicit resume action are visible. [Controlled baseline failures](AUDIO-RECOVERY-BASELINE-0.27.json).
- The earlier intermittent initial WebKit zero-signal finding **did not reproduce** before product changes: six isolated repetitions passed, then a repeated three-platform audio matrix passed 21 checks with six inapplicable skips. This does not establish that the startup issue is fixed. The new change addresses a separately demonstrated interruption/recovery gap. Failed audio tests now attach context, media and gain state for future diagnosis.

No WebView JavaScript errors were reported. This first-chapter smoke uses ADB and the real Capacitor bridge/SharedPreferences, not a Vite page. The emulator runs with audio output disabled, so advancing media transport is not audible-output evidence. [Native report](ANDROID-SMOKE-0.27.0.json).
- Strict TypeScript, Vite production build and Android/iOS Capacitor sync passed. Final main JavaScript **356.20 kB / 129.81 kB gzip**; CSS **54.32 kB / 12.38 kB gzip**. Music recordings and cue compositions are unchanged.
